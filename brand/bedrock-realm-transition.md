# Bedrock and Realm branding transition

Names chosen by the owner on 2026-10-07. **Naming is accepted; new artwork and
production exports are pending.** The September twelve-identity approval covers
the original collection, including the legacy OS family. It does not approve
new Bedrock or Realm identities.

## Names and roles

| Display name | Slug | Role |
| --- | --- | --- |
| The Wizard's Bedrock | `wizards-bedrock` | The Rust kernel, hardware support and kernel ABI; successor name for the existing wizards-os project |
| The Wizard's Realm | `wizards-realm` | The operating environment, shared Wizzy userland and intended Bedrock/Linux editions |

Use Bedrock and Realm after first mention. No separate nickname is selected.
Both projects follow the existing singular The Wizard's naming pattern.

Realm starts with documentation only and retains the CLOSED compiler-readiness
gate. The kernel folder/repository rename is separate active work. Names and
artwork do not establish implementation, release readiness or equivalent
security on the intended platforms.

## Work required before distribution

- Develop distinct illustrated lettering and instrument/landscape treatments
  for Bedrock and Realm while preserving the approved signature master.
- Decide their light/dark accent pairs. The existing os palette remains the
  legacy OS palette; it is not automatically assigned to both new identities.
- Produce light/dark transparent README logos, compact headers, icons,
  favicons, social previews and avatars using the existing production rules.
- Review the designs at actual sizes with the owner. Record approvals,
  source masters, generation/edit history and exact export provenance.
- Update production IDs, layout definitions, tokens, export manifest,
  public/private galleries and documentation together after approval.
- Migrate the consumers.json OS entry only after the real kernel directory
  identity is confirmed; add Realm's approved family and actual asset paths.
- Update product README artwork, kernel boot branding and future Realm chrome
  in their owning tasks. Preserve old source artwork and historical approvals.
- Validate hashes, dimensions, transparency, SVG safety and contrast before
  distributing approved exports to explicitly selected consumers.

Do not relabel the old OS artwork as a new approved identity, change a recorded
approval date, or run a broad asset sync during the active kernel/Ink sessions.
The production consumer map still contains their current paths and is not a
rename mechanism.

The public [brand guide](../BRAND.md) owns naming and visual rules. Project
registers own implementation status; this note owns the pending brand work.
